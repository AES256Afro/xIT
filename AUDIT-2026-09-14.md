# xIT code, performance and security sweep

> **Historical.** This reviewed 1.0.4. Version 1.0.7 removed page redirecting
> and the Nitter-based front-ends entirely, so findings about browse rules,
> redirect permissions, the timed pause and the reachability check no longer
> describe the extension. Kept as a record of what was found and fixed.

Reviewed version 1.0.4 at commit `3844017663132afcbebb10dea796ac3892d8d87b` on 14 September 2026. Local HEAD and remote `main` matched when inspected. Read `HANDOFF.md`, the runtime source, build tools, manifests, tests, and privacy documentation. The original findings below describe that revision. The user then authorized repairs; the resolution and validation record for version 1.0.5 follows the original review.

**1. [P1] Browse redirect fails to install in Chrome, while the UI reports it enabled.**

Locations: [reserved-path rule](https://github.com/AES256Afro/xIT/blob/3844017663132afcbebb10dea796ac3892d8d87b/src/lib/redirectors.js#L304), [profile rule](https://github.com/AES256Afro/xIT/blob/3844017663132afcbebb10dea796ac3892d8d87b/src/lib/redirectors.js#L280), [error handling](https://github.com/AES256Afro/xIT/blob/3844017663132afcbebb10dea796ac3892d8d87b/src/background.js#L245), [settings display](https://github.com/AES256Afro/xIT/blob/3844017663132afcbebb10dea796ac3892d8d87b/src/options/options.js#L90).

Loaded the generated Chrome extension in a fresh Chrome for Testing 151.0.7922.34 profile. Enabling browse redirect to xcancel produced zero dynamic rules. Chrome reported that rule 1001 exceeded the 2 KB compiled regex memory limit. Calling the native `declarativeNetRequest.isRegexSupported` API independently returned `memoryLimitExceeded` for both the reserved-path guard and the profile redirect expression. The guard is included for every nonempty browse configuration, so limiting the scope to tweets does not avoid the failure.

The options checkbox stayed checked and `browse-warn` stayed empty. The error is saved as `dnrError`, but neither popup nor options reads that value. Users cannot distinguish an active redirect from a failed configuration. The existing tests only apply JavaScript regular expressions and count generated rules; they do not exercise Chrome's compiler.

Split the reserved-path guard into smaller rules and reduce the profile expression's compiled cost, potentially moving source host matching into `requestDomains`. Validate generated expressions with the browser API, check installed rules, and show installation errors in the UI. Chrome documents both the [regex limit](https://developer.chrome.com/docs/extensions/reference/api/declarativeNetRequest#regex-rules) and the [atomic update behavior](https://developer.chrome.com/docs/extensions/reference/api/declarativeNetRequest#method-updateDynamicRules): an unsuccessful update leaves the previous rules in place.

**2. [P2] Concurrent settings saves lose completed user changes.**

Location: [load, merge, and write](https://github.com/AES256Afro/xIT/blob/3844017663132afcbebb10dea796ac3892d8d87b/src/lib/storage.js#L97).

Two saves can both read the same settings object, merge different patches, and then overwrite one another. In the actual extension worker, start with `toast: true` and `stripTracking: true`, then run `Promise.all([XITStore.save({toast:false}), XITStore.save({stripTracking:false})])`. Both calls resolve successfully, but the resulting settings are `toast: true, stripTracking: false`.

This can affect rapid controls or separate extension contexts such as the popup, options page, and in-page default selector. The background initialization queue serializes menu and rule refreshes; it does not serialize storage writes. Send settings mutations through a single writer in the background and merge each patch against the latest state there. A queue in each individual page would still permit races across contexts.

**3. [P2] Custom redirectors cannot be disabled.**

Location: [normalization of enabled IDs](https://github.com/AES256Afro/xIT/blob/3844017663132afcbebb10dea796ac3892d8d87b/src/lib/storage.js#L75).

After adding `c-test`, save `enabledIds: ['fxtwitter']`. Normalization produces `['fxtwitter', 'c-test']`. Every custom entry missing from the enabled list is added again on every load or save, so unticking it in Settings cannot persist. The comment promises explicit disabling, but the implementation cannot distinguish a newly added entry from an existing disabled entry.

Enable new custom entries when adding them. Preserve the saved enabled list during normalization, and test disabling, reloading, exporting, and importing a custom entry.

**4. [P2] Dropdown keyboard handling activates the wrong action.**

Locations: [Enter and Space handler](https://github.com/AES256Afro/xIT/blob/3844017663132afcbebb10dea796ac3892d8d87b/src/content/inject.js#L249), [Escape capture handler](https://github.com/AES256Afro/xIT/blob/3844017663132afcbebb10dea796ac3892d8d87b/src/content/inject.js#L599).

In the real content script mounted against the mock X page, focus the dropdown's Settings button and press Enter. It copies the first redirector's tweet URL and closes the menu instead of opening Settings. The menu handler prevents the native action for every Enter or Space event, then clicks the row with `xit-active`, regardless of the focused element. This also affects the Open, default, and clean-link buttons.

Escape has a separate focus problem: the window capture handler clears `menuOwner` before the menu's handler can restore focus. The focused element remains a row in the hidden menu. Restrict row activation to row navigation, leave focused buttons' native activation intact, and make one Escape handler close the menu and return focus to its trigger.

**5. [P2] Reachability checks contact disabled redirectors.**

Locations: [probe enumeration](https://github.com/AES256Afro/xIT/blob/3844017663132afcbebb10dea796ac3892d8d87b/src/options/options.js#L208), [request and timeout](https://github.com/AES256Afro/xIT/blob/3844017663132afcbebb10dea796ac3892d8d87b/src/options/options.js#L178), [privacy statement](https://github.com/AES256Afro/xIT/blob/3844017663132afcbebb10dea796ac3892d8d87b/PRIVACY.md#L26).

With only FxTwitter enabled, clicking Check which are reachable attempted requests to all 13 bundled hosts. This was measured in the real options page with `fetch` recorded locally and permission checks stubbed, so the audit itself did not contact those services. `renderList` creates badges for every configured redirector; `probeAll` uses every badge without checking `enabledIds`.

The privacy policy specifically limits this operation to enabled redirectors. Disabled services may also receive permission requests. Filter the operation through `enabledRedirectors(settings)` before checking access or fetching. The current loop is sequential, so 13 hosts timing out can take approximately 78 seconds, excluding permission prompts. Prevent overlapping runs and use bounded concurrency after collecting any required permissions.

**6. [P2] A failed copy persists a URL and timestamp without a recovery UI or retention limit.**

Location: [lastCopyFailure storage](https://github.com/AES256Afro/xIT/blob/3844017663132afcbebb10dea796ac3892d8d87b/src/background.js#L152).

When script injection fails, `notifyFailure` writes `{text, at}` to `storage.local.lastCopyFailure`. A native worker test using a nonexistent test tab saved the complete synthetic X URL, including its query string, and a timestamp. Repository inspection found no reader, expiry, or explicit deletion for this key. Reset to defaults removes only `settings`.

This contradicts the policy's description of storing only settings and adds persistent browsing-related data without a usable recovery feature. Remove the unused storage write, or define and document a short-lived recovery mechanism with an explicit clear operation. Existing installations also need cleanup of this key. The observed storage is local; no transmission was found.

**7. [P2] A menu creation failure can prevent browse redirect from being disabled.**

Locations: [initialization order](https://github.com/AES256Afro/xIT/blob/3844017663132afcbebb10dea796ac3892d8d87b/src/background.js#L365), [custom ID validation](https://github.com/AES256Afro/xIT/blob/3844017663132afcbebb10dea796ac3892d8d87b/src/lib/storage.js#L57).

`doInit` awaits `buildMenus` before calling `syncDnrRules`. Any menu failure therefore prevents rule synchronization, including removal of existing redirects after the user turns the feature off. The handoff mentions a partial menu after creation failure, but the impact also reaches network behavior.

To reproduce in native Chrome, seed one valid dynamic rule, then import a custom entry whose ID is `fxtwitter` while saving `browseRedirect: false`. Normalization accepts the ID because it checks duplicates only among custom entries. Native context-menu creation rejects the duplicate ID. The stored setting becomes false, but the seeded rule remains installed: one rule before and one after. This test deliberately seeded a valid rule because finding 1 prevents the current complete ruleset from being installed on a fresh profile.

Run menu refresh and rule synchronization independently so one failure cannot prevent the other operation. Reject imported IDs that collide with presets. Preserve separate errors for each subsystem and verify that disabling redirects always attempts rule removal.

**8. [P2] Custom targets beginning with `www.` are changed to a different host.**

Locations: [template host extraction](https://github.com/AES256Afro/xIT/blob/3844017663132afcbebb10dea796ac3892d8d87b/src/lib/redirectors.js#L207), [browse substitution](https://github.com/AES256Afro/xIT/blob/3844017663132afcbebb10dea796ac3892d8d87b/src/lib/redirectors.js#L276), [permission request](https://github.com/AES256Afro/xIT/blob/3844017663132afcbebb10dea796ac3892d8d87b/src/options/options.js#L280).

For `https://www.example.com/{path}{query}`, copy conversion preserves `www.example.com`, but `templateHost` returns `example.com`. Browse rules, reachability checks, and permission requests use that stripped value. The apex and `www` host may serve different applications, and permission for one does not establish access to the other.

Use URL parsing to preserve the destination hostname or origin exactly. Keep any normalized comparison form separate from the value used for navigation, permission checks, and requests. Include custom hosts with `www.`, ports, and IPv6 in coverage.

**9. [P2] Native-copy success is announced before clipboard success.**

Locations: [copied event](https://github.com/AES256Afro/xIT/blob/3844017663132afcbebb10dea796ac3892d8d87b/src/content/main-world.js#L48), [clipboard invocation](https://github.com/AES256Afro/xIT/blob/3844017663132afcbebb10dea796ac3892d8d87b/src/content/main-world.js#L60).

`transform` sends the `copied` event before the original clipboard operation runs. In a VM reproduction where the original writer rejects with `clipboard denied`, the wrapper still emits a successful copied event. The isolated script displays that as success even though the clipboard did not change. The `ClipboardItem` path has the same ordering and may later fall back to the original text.

Keep transformation free of notifications. Announce success only after the final clipboard operation resolves, and preserve the original error behavior when it fails.

**Additional correctness observations**

- The reserved-path guard has no path-segment boundary. Its current expression matches `/homegrown`, `/topicsmith`, and `/jobsmith`, although the parser identifies each as a profile. This would incorrectly exempt those profiles once the compiler failure in finding 1 is repaired. Add an end, slash, query, or fragment boundary and test representative profile names. See [guardRules](https://github.com/AES256Afro/xIT/blob/3844017663132afcbebb10dea796ac3892d8d87b/src/lib/redirectors.js#L304).
- Thread Reader URLs are recognized as mirror URLs but their path is not decoded. Converting `https://threadreaderapp.com/thread/20.html` to FxTwitter returns `https://fxtwitter.com/thread/20.html`, an invalid tweet path. Either support the source-specific path shape or refuse unsupported retargeting instead of returning `ok: true`. See [parse](https://github.com/AES256Afro/xIT/blob/3844017663132afcbebb10dea796ac3892d8d87b/src/lib/redirectors.js#L124).

**Performance measurements**

Measured the actual isolated content script in headless Chrome with mock tweet DOMs. Each workload made 60 text replacements in an unrelated node outside the articles. Timings cover scan callbacks after initial button insertion, excluding initial rendering. They are local synthetic measurements, not a live X timeline benchmark.

| Mounted articles | Full scans | Median per scan | 95th percentile | Total scan time |
| --- | ---: | ---: | ---: | ---: |
| 50 | 31 | 0.1 ms | 0.2 ms | 2.5 ms |
| 200 | 31 | 0.3 ms | 0.5 ms | 10.1 ms |
| 1,000 | 31 | 1.4 ms | 1.5 ms | 43.4 ms |

[The observer](https://github.com/AES256Afro/xIT/blob/3844017663132afcbebb10dea796ac3892d8d87b/src/content/inject.js#L585) schedules a [full-document query](https://github.com/AES256Afro/xIT/blob/3844017663132afcbebb10dea796ac3892d8d87b/src/content/inject.js#L422) for any child-list mutation in the body. Frame coalescing limits frequency, but unrelated updates still cause work proportional to mounted content. These timings do not establish a user-visible stall. Inspect added nodes, scan only affected article subtrees, and ignore extension-owned changes if optimizing this path. A 60-frame idle interval recorded one pending cleanup scan and no continuing scan loop.

The options reachability loop has a larger predictable delay: its six-second timeout is applied serially to every configured host. Finding 5 addresses both that delay and its request scope.

**Security boundary review**

The source has no runtime package dependencies, dynamic code evaluation, remote script loading, analytics client, or embedded credential found by the targeted source scan. User names, templates, and copy feedback are inserted through text nodes or `textContent`. The main-world bridge receives page-controlled messages, but the isolated receiver only handles configuration handshakes and toast text; it does not forward those messages to privileged tab or settings actions. A forged main-world configuration is not, by itself, evidence of an extension privilege escape because page code already controls that world.

The generated manifests retain explicit X/Twitter host access and the handoff's intentional optional `*://*/*` declaration. This review found concrete privacy issues in request selection and local retention, described in findings 5 and 6. It did not establish remote code execution or cross-origin data theft.

**1.0.5 resolution record**

All nine findings and both additional correctness observations were repaired on
14 September 2026. The observer optimization was also implemented.

| Finding | Change | Regression evidence |
| --- | --- | --- |
| 1. Rejected browse rules and misleading status | Split reserved routes into separate guards. Generate bounded profile rules per scheme and source host with URL transforms. Check the native compiler and installed rules; display pending, active, off, or error status in both interfaces. | Native Chrome accepts every generated pattern. Chrome and Firefox each install 40 rules for the default tweet/profile scope. Failure injection leaves no old rules and displays the error in both interfaces. |
| 2. Lost settings writes | Route mutations from every context through one background writer. Merge individual scope/list operations against the latest stored settings. | Separate native Chrome pages and native Firefox messaging preserve concurrent changes; unit tests cover nested scopes, additions, and write failures. |
| 3. Custom entries re-enabled | Enable custom entries only when added; preserve their saved enabled state on load and import. | Disable, reload, import, and concurrent-add checks pass. |
| 4. Wrong keyboard action | Preserve native button activation and return focus to the trigger on Escape. Retain menu scroll and focus across settings updates. | Native Chrome checks Settings, clean copy, Open, default selection, Escape, and scrolling. |
| 5. Excess reachability requests | Check enabled entries only, request their HTTPS access once, cap concurrency at three, and prevent overlapping runs. Omit credentials/referrers and do not follow redirects. | One enabled preset produces one request. All 13 presets produce 13 requests with at most three in flight. Denied access produces zero requests. |
| 6. Retained failed-copy URLs | Stop writing the record and delete legacy data during startup and reset. Correct privacy documentation. | A seeded record is deleted; forced failed copies do not recreate it. |
| 7. Menu failures retain redirects | Run menu updates, redirect updates, and legacy cleanup independently. Reject imported preset ID collisions and duplicate custom IDs. | Injected menu creation failure cannot prevent removal of active rules. Import tests verify ID isolation. |
| 8. Changed custom destinations | Parse exact hostnames and origins, preserving `www.`, ports, and IPv6. Reject template credentials and substitution escape characters. | Conversion and permission tests preserve the intended host; native Chrome installs custom `www.`/port and IPv6 destinations. |
| 9. Premature clipboard success | Announce success only after the original writer resolves. Limit fallback to data preparation failures; propagate native write failures without retrying. | Deferred success, failed writes, preserved clipboard formats, preparation fallback, and malformed configuration tests pass. |
| Reserved prefixes | Match complete reserved segments and exact bypass values. | `homegrown` is treated as a profile; `home`, settings routes, and exact bypass requests remain protected. |
| Thread-tool retargeting | Recover the tweet ID from Thread Reader App and Unroll Now URLs before conversion. | Both formats convert to an `i/web/status/ID` URL; unrelated tool paths are rejected. |

The final pass also prevents a delayed initial status read from overwriting a
newer status event. Control values are captured before awaiting permissions so
an unrelated settings refresh cannot replace the user's pending selection.
Successful redirect status uses normal text styling; errors remain distinct.
